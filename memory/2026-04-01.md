## Project Overview
Built a self-automating GitHub Pages website "Quant Frontier" that aggregates, summarizes, and ranks quantitative finance research and news, updated every 5 minutes.

### 2. Design & Branding Evolution

### 3. Technical Challenges & Solutions

#### Challenge 1: Broken Website Loading
- **Problem**: Website stuck on "Loading..." due to corrupted `index.html` (JavaScript functions truncated)
- **Solution**: Created static HTML versions (`index_static.html`, `index_simple_final.html`) with embedded content
- **Result**: Website loads immediately with 15 complete quant finance items

#### Challenge 2: Archive Button Failures
- **Problem**: All archive services (`archive.ph`, `archive.today`, Google Cache) block automated access (HTTP 429)
- **Discovery**: Server IP completely blocked by archive.* network
- **Solution**: Removed archive links entirely to avoid block pages
- **Alternative**: Added source attribution links so users can access originals directly

#### Challenge 3: News Article Access
- **Problem**: Major financial news sites (WSJ, FT, Bloomberg, Reuters) block access (HTTP 403)
- **Solution**: Used text extraction services and focused on publicly accessible sources
- **Current**: Embedded 4 real financial news articles with working links

#### Challenge 4: Dynamic Loading Issues
- **Problem**: CORS blocking JSON feed loading from GitHub Pages
- **Solution**: Deployed final static version with all content embedded in HTML
- **Fallback**: Created self-healing JavaScript that tries multiple endpoints, falls back to static content

### 6. Key Learnings
1. **Static over Dynamic**: For reliability, embedded HTML content beats dynamic JSON loading
2. **Archive Services Block**: Archive.* network universally blocks automated access
3. **News Site Protection**: Major financial publishers have strong anti-bot protection
4. **CORS Challenges**: GitHub Pages JSON feeds have CORS limitations
5. **User-Centric Design**: Source attribution in brackets is more useful than broken archive links
